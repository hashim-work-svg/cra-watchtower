# Security Policy: CRA Vulnerability Watchtower

## Threat Model & Implemented Mitigations

`cra-watchtower` processes Software Bills of Materials (SBOMs), often generated by third-party build pipelines, suppliers, or open-source repositories.

| Risk Area | Mitigation Implemented | Residual Risk |
| :--- | :--- | :--- |
| **Malformed / Huge SBOMs (DoS)** | Strict 10MB input read limit (`MaxSBOMSizeBytes` via `io.LimitReader`), JSON syntax validation, bounded memory allocation. | Highly fragmented valid JSON requiring parsing time. |
| **PURL Injection / Spoofing** | Validation via official `packageurl-go` specification parser; canonicalization of schemes, ecosystems, and namespaces. | Unrecognized custom package types defaulted to `generic`. |
| **Vulnerability Data Tampering** | Synced vulnerability and KEV catalogs verified via SHA-256 checksums (`.sha256` files) and offline embedded fixtures fallback. | Stale local vulnerability data if synchronization is not scheduled. |
| **Premature / Inaccurate Reporting** | All notification drafts are generated locally as Markdown with prominent `[REQUIRED]` human-action markers; zero automatic network transmissions to authorities. | Human operator filing notifications without verification. |

## Reporting a Vulnerability

If you identify a security issue in `cra-watchtower`, please report it responsibly by opening a private [GitHub Security Advisory](https://github.com/hashim-work-svg/cra-watchtower/security/advisories/new).
